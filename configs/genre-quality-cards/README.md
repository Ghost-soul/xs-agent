# 创作卡库

创作卡只分题材与叙事，均由作者手选。叙事卡以能联想到具体故事的内容标签为主体。

| 目录 | 用途 | 例子 |
| --- | --- | --- |
| `genres/` | 提供世界背景、时代环境和基础设定 | 西方奇幻、古典仙侠、现代言情 |
| `narrative/` | 引入人物关系、身份处境、职业事件、故事机制、经典桥段或结果倾向 | 百合、真假千金、科举文、时间循环、先婚后爱、悲剧 |

完整清单见 [活动叙事卡索引](NARRATIVE_INDEX.md)。每张都说明要加入什么内容、怎样展开、
事件如何改变人物处境，以及与其他卡怎样形成一条剧情线。视角、节奏、语言作为实现这些内容的方法。
例如“百合＋真假千金”让身份调查与家庭安排改变两名女性的相处，并推动爱情选择；
“末世囤货＋爽文”让物资与避难所接连到手、及时兑现优势，沿用作者指定的连续成功方向。

世界机制真实发生在故事里：时间循环、职业觉醒等写明适用前提。
它们依据作者选择且与正式世界规则相容后进入计划，不能仅因选卡就被当作已发生事实。
卡中桥段是可选择的发展内容，不是每章逐项完成的清单；没有题材评分、百分比或新增验收门槛。

新选卡方式为一张主题材、最多一张副题材，以及独立多选的叙事卡。
在“质量偏好”页保存项目默认组合，在“创作”页可从完整卡库调整本阶段的主副题材和多张叙事卡。
叙事卡可按名称查找，不占题材位，也不设固定张数上限；预览仍核算全部所选卡的输入容量与费用。
一次预览完整冻结本次所选卡，不加入未选的项目默认卡，不自动截断卡文。
卡库扩充不将整个目录塞入请求。Chief 把内容方向落实为具体事件、人物选择与后果，
Writer 依据有效计划和必要背景写作，继续不接整卡。详见
[独立选卡说明](../../docs/separate-card-selection-2026-09-23.md)；加载状态以 CURRENT_STATE 为准。

内容标签卡主要使用 `4.0`；全民转职、恐怖惊悚、女强经审核优化为 `4.1`，稳定 ID 保持。其他活动卡保留各自版本。
作者后续修改及新增的卡沿用原稿 `5.0`／`5.1`，本次只整理注册分隔线、代码围栏、缩进、换行与文件扩展名，
名称、ID、版本和正文保持作者原稿。格式说明与原稿备份见[格式整理记录](../../docs/card-format-2026-09-24.md)。
作者随后要求删除二十张叙事卡，已从活动目录和索引移除；清单与兼容边界见
[删除记录](../../docs/narrative-card-removal-2026-09-23.md)。新建选择不再提供这些卡，
历史批次继续读取原有冻结文本、SHA 和合同，删除不修改正式资料或已保存调用。

原一百张卡的拆分、别名与旧 ID 承接属于历史建设记录，见
[内容标签叙事卡](../../docs/narrative-content-cards-2026-09-23.md)。
审核后，作者进一步批准删除灵气复苏、军事战争、文青致郁、侦探推理，并优化全民转职、恐怖惊悚、女强。
三张优化卡分别聚焦职业立足、安全失效后的求生、决定权的取得与运用；背景与写法服务具体行动及后果。
原文与 SHA 另存于 `backups/narrative-audit-apply-20260923-before/`，实施与兼容边界见
[审核后处理记录](../../docs/narrative-card-audit-application-2026-09-23.md)。
恐怖惊悚、暗黑权谋、男性向情感爽文、群像悲剧继续作为补充卡。

所有卡使用 UTF-8、LF。加载器只扫描根目录和 `genres/`、`narrative/` 中带注册 front matter 的 Markdown，
索引、说明与备份不作为卡注入。本轮修改前完整原卡及逐文件 SHA 清单位于
`backups/narrative-hundred-20260923-before/`，更早的所有备份继续保留。
实现与兼容说明见 [内容标签叙事卡](../../docs/narrative-content-cards-2026-09-23.md)，实际验证和加载见
